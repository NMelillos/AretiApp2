## Report safeguards and scope

The report uses committed import time when timezone provenance is known, otherwise import-ID fallback is visibly unverified. A newer incomplete import remains selected and visible. Missing periods, balances, precision, source rows, account identity or usable FX never become invented values. The numeric report is not historical data repair. Unknown bank/account identifiers cannot match unrelated rows; different currencies remain separate. Renamed Setup and stored source labels are both shown, with mismatch warnings and no asserted transfer of ownership. SQL values remain internal fixed column references and enumerated aliases, not user-supplied SQL.

HTML, print and Excel share one dataset. Known currency display uses two decimal places without rewriting stored amounts. Finer or unknown currency precision remains explicit. Excel uses numeric cells within its precision contract and literal strings outside it; text that resembles formulas stays literal. Eligible USD equivalents contribute to an explicitly PARTIAL total. Source reconciliation is not verified merely because metadata and storage are suitable; card/liability netting remains unapproved. Records outside current Setup remain a historical-audit responsibility; this is a report of current Setup accounts, not a complete orphan-record census.
